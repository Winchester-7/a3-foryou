# Развёртывание на сервере и работа с админ-панелью

Автор проекта: **Erbol king**

Сайт — одно приложение (Next.js), которое содержит и витрину, и админ-панель, и API.
Внешняя база данных не нужна: данные лежат в JSON-файлах и фото в одной папке
(Docker-том `/data`). Всё, что меняют в админ-панели, видно на сайте со следующего
запроса — без пересборки и перезапуска.

```
Cloudflare ──► Nginx (сервер) ──► контейнер a3-site :3000 ──► том /data
                                     │                         ├─ tiles.json       керамогранит
   app.a3.kg, backend.a3.kg          │                         ├─ doors.json       двери
   остаются как были (не трогаем)    │                         ├─ sofas.json       диваны
                                     │                         ├─ portfolio.json   портфолио
                                     │                         ├─ promotions.json  акции
                                     │                         ├─ settings.json    контакты
                                     │                         ├─ leads.json       заявки с сайта
                                     └──────────────────────── └─ uploads/         загруженные фото
```

## 1. Переменные окружения контейнера

На сервере не хранится ни `docker-compose.yml`, ни `.env`: значения берутся из переменных
GitLab CI и передаются контейнеру при выкатке.

| Переменная | Откуда | Значение |
|---|---|---|
| `ADMIN_PASSWORD` | CI-переменная проекта `ADMIN_PASSWORD_DEV` / `ADMIN_PASSWORD_PROD` | пароль входа в `/admin` (без него админка выключена) |
| `ADMIN_SESSION_SECRET` | `ADMIN_SESSION_SECRET_DEV` / `_PROD` | длинная случайная строка для подписи cookie |
| `DATA_DIR` | задан в образе | `/data` — папка тома с данными |
| `NEXT_PUBLIC_SITE_URL` | при сборке, `SITE_URL_DEV` / `SITE_URL_PROD` | `https://a3.kg` |
| `NEXT_PUBLIC_PLANNER_URL` | при сборке | адрес 3D-планировщика |

## 2. Сборка и поставка (GitLab CI/CD)

Схема такая же, как у остальных проектов: раннер собирает образ, кладёт его в GitLab
Registry, заходит на сервер по SSH, тянет образ и пересоздаёт контейнер
(`deploy/deploy.sh`). Старый контейнер останавливается только после того, как новый
ответил на `/api/health`; если не ответил, старый запускается обратно.

Этапы (`.gitlab-ci.yml`): `typecheck` → `build` → `deploy`. Раннер выбирается тегом `a-3`.

- ветка `dev` → образ `:dev` → контейнер `a3-site-dev`, порт `3001` → **a3-dev.xyz**, выкатка автоматическая
- ветка `main` → образ `:latest` → контейнер `a3-site`, порт `3000` → **a3.kg**, выкатка кнопкой «Run» (manual)

Контейнер слушает только `127.0.0.1:<порт>` на сервере; данные лежат в Docker-томах
`a3-data` (prod) и `a3-data-dev` (dev).

Что нужно один раз настроить:

1. Групповые переменные (уже есть): `DEPLOY_SERVER_DEV`, `DEPLOY_SERVER_PRODUCTION`, `SSH_PRIVATE_KEY`.
2. Переменные проекта (Settings → CI/CD → Variables, Masked, без пробелов в значениях):
   `ADMIN_PASSWORD_DEV`, `ADMIN_PASSWORD_PROD`, `ADMIN_SESSION_SECRET_DEV`, `ADMIN_SESSION_SECRET_PROD`.
3. По желанию: `DEPLOY_USER` (по умолчанию `root`), `A3_PORT_DEV` / `A3_PORT_PROD`
   (по умолчанию 3001 / 3000 — должны быть свободны), `A3_DOCKER_NETWORK` (если Nginx в контейнере).
4. Раннеру нужен Docker-in-Docker (используется `docker:26-dind`).

`docker-compose.yml` в репозитории оставлен для запуска на собственном сервере без CI,
в этой схеме не используется.

## 3. Nginx

У сервера свой Nginx — достаточно добавить в него два виртуальных хоста по образцу
`deploy/nginx/a3-site.conf`: `a3.kg` и `www.a3.kg` → `127.0.0.1:3000`,
`a3-dev.xyz` → `127.0.0.1:3001`. Записи для `app.a3.kg` и `backend.a3.kg` не меняются.
В `client_max_body_size` стоит 12 МБ — под загрузку фото (до 10 МБ).

## 4. Админ-панель

Адрес: `/admin`. Разделы:

| Раздел | Что можно |
|---|---|
| Керамогранит | коллекции и позиции: создать, переименовать, удалить; остатки по форматам (шт. и м²); фото; бренд и тип |
| Остатки Excel | загрузка складской таблицы `.xlsx` (лист на завод): предпросмотр изменений, затем «Применить» |
| Двери | модели: вид (межкомнатная / входная), серия, стиль, цвета, размеры, фото |
| Диваны | модели, размеры, ткани и цвета, фото |
| Портфолио | проекты с фото |
| Акции | скидки и предложения |
| Заявки | обращения с форм сайта, статус «обработана», выгрузка в CSV |
| Контакты | телефон, WhatsApp, адрес, часы работы, описание в подвале |

### Загрузка остатков из Excel

Раздел «Остатки Excel» принимает ту же таблицу, из которой собирался каталог: по листу на
каждый завод, столбцы — завод, наименование, размер (м² в штуке), штук, м². Файл
сопоставляется с позициями каталога тремя способами, по убыванию надёжности:

1. по названию строки из таблицы (оно запоминается при каждой загрузке);
2. по артикулу внутри завода (`G202`, `K101`);
3. по похожему названию (для заводов без артикулов, порог 80 %; процент виден в предпросмотре).

Перед записью показывается отчёт: сколько строк найдено, как изменился остаток в м²,
какие позиции новые, у каких остаток обнулится. Применять нужно явно; если каталог
изменили между предпросмотром и «Применить», загрузка отклоняется. Две галочки:
«обнулить позиции, которых нет в файле» (только у заводов с листом в файле) и «добавить
новые позиции» (попадут в коллекцию завода без фото). Остатки в файле — полная
замена, а не прибавка: загружайте всегда актуальный полный список.

Защита от потери данных: если два человека открыли один раздел, сохранение второго
будет отклонено с просьбой обновить страницу; сервер проверяет данные перед записью
(повторяющиеся адреса, пустые названия и т. п.), поэтому опечатка не «положит» сайт.

## 5. Резервная копия и перенос

Всё состояние — том `a3-data`:

```bash
docker run --rm -v a3-data:/data -v "$PWD":/backup alpine tar czf /backup/a3-data.tgz -C /data .
```

Восстановление — распаковать архив в тот же том. Первый запуск на пустом томе
стартует с данных, вшитых в образ; после первого сохранения в админке данные живут в томе.

## 6. Что не входит

- Реальные остатки «на лету» из бэкенда дилерского приложения: сайт их не запрашивает,
  остатки вносятся в админ-панели. Если понадобится, добавляется отдельным API-адаптером.
- 3D-планировщик — отдельное статическое приложение (`planner/`). Каталог он берёт
  из собственной копии; после крупных изменений в каталоге выполните `npm run data` в
  папке `planner/` и пересоберите его. Размещать можно где угодно (Netlify, Nginx).
- Переводы интерфейса на кыргызский — словарь `src/lib/i18n/ky.ts`; тексты, добавленные
  в админ-панели, остаются на том языке, на котором введены.
