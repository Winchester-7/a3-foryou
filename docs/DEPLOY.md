# Развёртывание на сервере и работа с админ-панелью

Автор проекта: **Erbol king**

Сайт — одно приложение (Next.js), которое содержит и витрину, и админ-панель, и API.
Внешняя база данных не нужна: данные лежат в JSON-файлах и фото в одной папке
(Docker-том `/data`). Всё, что меняют в админ-панели, видно на сайте со следующего
запроса — без пересборки и перезапуска.

```
Cloudflare ──► Nginx (сервер) ──► контейнер a3-site :3000 ──► том /data
                                     │                         ├─ tiles.json       керамогранит
   app.a3.kg, backend.a3.kg          │                         ├─ doors.json       двери
   остаются как были (не трогаем)    │                         ├─ sofas.json       диваны
                                     │                         ├─ portfolio.json   портфолио
                                     │                         ├─ promotions.json  акции
                                     │                         ├─ settings.json    контакты
                                     │                         ├─ leads.json       заявки с сайта
                                     └──────────────────────── └─ uploads/         загруженные фото
```

## 1. Переменные окружения (`.env` рядом с `docker-compose.yml`)

| Переменная | Обязательно | Значение |
|---|---|---|
| `ADMIN_PASSWORD` | да | пароль входа в `/admin` (без него админка выключена) |
| `ADMIN_SESSION_SECRET` | желательно | длинная случайная строка для подписи cookie |
| `DATA_DIR` | задан в образе | `/data` — папка тома с данными |
| `NEXT_PUBLIC_SITE_URL` | при сборке | `https://a3.kg` (в образ подставляет CI) |
| `NEXT_PUBLIC_PLANNER_URL` | при сборке | адрес 3D-планировщика |

## 2. Сборка и поставка (GitLab CI/CD)

В репозитории уже лежат `Dockerfile`, `docker-compose.yml` и `.gitlab-ci.yml`.

- ветка `dev` → образ `:dev` → контейнер на порту `3001` → **a3-dev.xyz**
- ветка `main` → образ `:latest` → контейнер на порту `3000` → **a3.kg**

Что нужно один раз настроить:

1. Создать репозиторий в GitLab и запушить код (в нём есть папка `planner/` — 3D-планировщик,
   в Docker-образ магазина она не попадает, см. `.dockerignore`).
2. В GitLab → Settings → CI/CD → Variables задать `SSH_PRIVATE_KEY`, `DEPLOY_HOST`, `DEPLOY_USER`
   (и при необходимости `DEV_DIR` / `PROD_DIR`, `SITE_URL_DEV` / `SITE_URL_PROD`).
3. На сервере создать папки `/srv/a3-site-dev` и `/srv/a3-site-prod`, положить туда
   `docker-compose.yml` и `.env` (для dev: `A3_PORT=3001`, `A3_CONTAINER=a3-site-dev`).
4. Раннеру нужен Docker-in-Docker (используется `docker:26-dind`).

## 3. Nginx

Готовый фрагмент — `deploy/nginx/a3-site.conf`: `a3.kg` и `www.a3.kg` → `127.0.0.1:3000`,
`a3-dev.xyz` → `127.0.0.1:3001`. Записи для `app.a3.kg` и `backend.a3.kg` не меняются.
В `client_max_body_size` стоит 12 МБ — под загрузку фото (до 10 МБ).

## 4. Админ-панель

Адрес: `/admin`. Разделы:

| Раздел | Что можно |
|---|---|
| Керамогранит | коллекции и позиции: создать, переименовать, удалить; остатки по форматам (шт. и м²); фото; бренд и тип |
| Двери | модели: вид (межкомнатная / входная), серия, стиль, цвета, размеры, фото |
| Диваны | модели, размеры, ткани и цвета, фото |
| Портфолио | проекты с фото |
| Акции | скидки и предложения |
| Заявки | обращения с форм сайта, статус «обработана», выгрузка в CSV |
| Контакты | телефон, WhatsApp, адрес, часы работы, описание в подвале |

Защита от потери данных: если два человека открыли один раздел, сохранение второго
будет отклонено с просьбой обновить страницу; сервер проверяет данные перед записью
(повторяющиеся адреса, пустые названия и т. п.), поэтому опечатка не «положит» сайт.

## 5. Резервная копия и перенос

Всё состояние — том `a3-data`:

```bash
docker run --rm -v a3-data:/data -v "$PWD":/backup alpine tar czf /backup/a3-data.tgz -C /data .
```

Восстановление — распаковать архив в тот же том. Первый запуск на пустом томе
стартует с данных, вшитых в образ; после первого сохранения в админке данные живут в томе.

## 6. Что не входит

- Реальные остатки «на лету» из бэкенда дилерского приложения: сайт их не запрашивает,
  остатки вносятся в админ-панели. Если понадобится, добавляется отдельным API-адаптером.
- 3D-планировщик — отдельное статическое приложение (`planner/`). Каталог он берёт
  из собственной копии; после крупных изменений в каталоге выполните `npm run data` в
  папке `planner/` и пересоберите его. Размещать можно где угодно (Netlify, Nginx).
- Переводы интерфейса на кыргызский — словарь `src/lib/i18n/ky.ts`; тексты, добавленные
  в админ-панели, остаются на том языке, на котором введены.
